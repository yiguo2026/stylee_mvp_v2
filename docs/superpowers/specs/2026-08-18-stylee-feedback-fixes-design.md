# Stylee 用户测试反馈修复设计

## 目标

在不迁移历史衣橱数据、不改变透明主图存储原则、不增加每次搭配的生图调用的前提下，修复用户测试发现的六类问题，并增加一个可供同事体验的线上穿搭画布 Demo 入口。

## 已确认决策

1. **帽子与围巾搜索分离**：保留数据库一级分类 `帽巾`，搜索 `帽/帽子` 时不匹配围巾，搜索 `围巾/丝巾` 时不匹配帽子。
2. **编辑式穿搭画布**：客户端使用现有透明主图确定性排版，不调用生图模型。服饰按角色和数量选择模板，无配饰时不保留空位。
3. **鞋履比例和位置**：鞋履视觉比例小于上装/下装；三件基础搭配中鞋履位于裤装右下侧，不覆盖裤装主体。
4. **识别专用压缩副本**：原图仅在模型服务内部生成最长边不超过 1280、约 1MP、JPEG 质量 82 的识别副本；原图继续用于抠图、透明主图和持久化。
5. **透明主图质量**：透明像素继续透出运行时语义底色；棋盘格、白色矩形或其他可见背景不能作为合格透明主图。直接抠图质检不合格时进入一次完整图像编辑流程。
6. **衣橱统一底色**：衣橱卡片媒体区使用 `surface.input` 语义底色，不生成或保存合成背景图。
7. **账号隔离**：每个导入任务绑定 `ownerUserId`。登录用户变化或退出时停止并移除旧账号任务；重试、确认和保存均校验任务所有者。
8. **试穿无文字**：保留时尚杂志摄影质感，但明确要求画面不是杂志封面，不生成任何文字、标题、字母、数字、Logo 或水印。
9. **发布流程**：先完成本地实现、全量测试和视觉验收；用户确认无问题后才推送并创建 GitHub PR。

## 已验证根因

用户原图 `1672 × 2508 / 5.6MB PNG` 真实请求返回：

- HTTP `504`
- `request_id=codex-repro-msyduwz4`
- `stage=A1.multi_vision_recognize`
- `error_type=ProviderTimeoutError`
- 服务端约 52 秒，上游截止时间 50 秒

同图机械压缩为 `853 × 1280 / 444KB JPEG` 后返回 HTTP `200`，约 37 秒，正确识别上装、下装、腰带、鞋履和包袋。因此根因是原始高分辨率 PNG 进入模型前的传输、解码和推理总耗时超出上游截止时间，而不是图片中没有服饰。

## 穿搭画布规则

画布按服饰角色划分核心服装、中型单品和小型配饰：

- 外套：100%
- 下装/连体装：95%
- 内搭/上装：88%
- 鞋履和包袋：约 68–72%
- 帽子/围巾：约 65–68%
- 小型饰品：约 55%

布局：

- `3件基础`：上装与下装构成中央轴线，鞋履缩小并放在下装右下侧，不覆盖裤腿。
- `4件叠穿`：外套向左后方错位，内搭居中靠前，下装延续中央轴线，鞋履放在底部侧方。
- `5–6件配饰`：核心穿搭尺寸不缩小；包、帽子、围巾利用周围自然留白环绕，不显示固定右栏。
- `7件以上`：核心穿搭保持尺寸，额外配饰进入底部横向配饰带。
- 连体装替代上装+下装的中央轴线，不为不存在的槽位保留空白。

主画布不逐件显示名称；名称、拥有状态、收藏和替换操作保留在画布下方单品列表。

## Demo 入口

新增受登录保护的 `/outfit-layout-demo` 路由，并在 `更多设置 → 实验功能` 增加 `穿搭布局 Demo`。Demo 复用正式 `StyleeOutfitCanvas` 组件和仓库预置透明素材，支持切换 3/4/6 件状态，验证同事看到的就是正式实现逻辑，而不是单独维护的静态样例。

## 数据和安全边界

- 不新增数据库表或迁移。
- 不把导入任务持久化到本地存储或 Supabase。
- 不把服务端密钥移入 Expo 客户端。
- 不读取其他用户任务，不允许旧任务在新账号下继续处理。
- 识别压缩副本只存在于单次服务请求内，不落库。

## 验收标准

- 搜 `帽` 不出现围巾；搜 `围巾` 不出现帽子；一级 `帽巾` 筛选仍显示两者。
- 用户给出的原图经过服务端识别预处理后可在 50 秒上游期限内返回 5 件识别结果。
- 原始素材继续用于标准化和持久化。
- 切换账号后旧失败任务立即消失且不能重试/保存到新账号。
- 衣橱卡片统一浅灰语义底色；棋盘格结果不能成为透明主图。
- AI 试穿提示词和参数禁止文字、Logo 和水印，但保留杂志摄影质感。
- 3/4/6 件画布状态无空占位、无被鞋履遮挡的裤装，320/375/393/430/768 宽度可用。
- Demo 入口与正式推荐结果共用同一布局组件。
