# Stylee Design System v3.8

This directory is the implementation source for released Stylee UI foundations and components.

## Source of truth

- `design-tokens/stylee-v3.8.tokens.json` is the canonical Tokens Studio source.
- `tokens.ts` is generated by `npm run tokens:build`; do not edit it directly.
- Run `npm run tokens:check` to verify that the JSON and TypeScript output match.
- Product components consume semantic tokens (`surface`, `text`, `border`, `action`, `status`).
- Primitive colors are only for defining semantic tokens.
- Existing values in `constants/theme.ts` remain a compatibility layer while screens migrate.

## Tokens Studio GitHub sync

Use a single-file GitHub sync provider:

- Repository: `yiguo2026/stylee_mvp_v2`
- Branch: `tokens-sync`
- Storage type: `File`
- File path: `design-tokens/stylee-v3.8.tokens.json`

Always pull after first connecting. For later design updates:

1. Pull the latest Tokens from `tokens-sync`.
2. Update Tokens in Figma and push with a descriptive commit message.
3. Run `npm run tokens:build`.
4. Run `npm run check` and open a pull request to `main`.

## Engineering rules

1. Do not add raw hex colors or one-off button/card geometry to product screens.
2. Reuse a released component before creating a new page-local equivalent.
3. New reusable APIs must include disabled/loading/pressed behavior and accessibility labels.
4. Interactive targets are at least 44 × 44 pt.
5. Validate changed screens at 320, 375, 393, 430, and 768 pt widths.
6. A component change and its consuming screen ship in the same pull request.
7. New raw colors and legacy `Colors`/`Spacing`/`Radius`/`Shadow` usage fail `npm run design-system:check`.
8. New raw font size, line height, tracking, or font family declarations in product screens also fail the guard.
9. Intentional exceptions require `// ds-exception: <reason>` and PR documentation.

## Four-level typography

All product text must use one of four semantic roles:

| Role | Specification | Use |
|---|---|---|
| `display` | 24/30, display semibold | Page titles and major empty-state titles |
| `heading` | 18/24, display medium | Sheet titles, section titles, grouped-context headings |
| `content` | 15/22, UI medium | Card titles, buttons, tabs, chips, inputs, primary values |
| `support` | 12/18, body regular | Descriptions, metadata, field labels, help and status text |

Color, alignment, and truncation may respond to context. Font family, size,
line height, weight, and tracking must stay attached to the role. The Stylee
wordmark and icon/emoji glyphs are not product typography and are the only
default exceptions.

## Choice chip density

- `StyleeChoiceChip` is the active vNext shared component for compact selection controls.
- Choice chips are for compact single- or multi-select filters, not primary navigation.
- Their default visual height is 32 pt with 12 pt horizontal padding and an 8 pt radius.
- A 44 pt minimum touch area is preserved with hit slop instead of making the visible chip 44 pt tall.
- Use the shared component for filter tags and category selectors; do not reproduce its geometry in a screen.

## Wardrobe grid density

The wardrobe home grid uses `ds.component.wardrobeGrid`. Its reference
composition is a 393 × 852 pt iPhone viewport at the default text size:

- two columns and three fully visible rows between the page controls and Tab Bar;
- 16 pt screen padding, 8 pt column gap, and 8 pt row gap;
- 44 pt header and search control, followed by a 32 pt choice-chip row;
- card media uses a 4:3 `contain` frame so full garments remain visible;
- the information area is 48 pt minimum and contains one Content line plus one
  Support line.

The header owns the add action as a trailing 44 × 44 pt touch target. Do not
place a floating add button over the grid. The six-card target applies to the
stable state without a keyboard or temporary import/confirmation banner.
Dynamic Type and shorter viewports may show fewer complete rows; accessibility
must not be sacrificed to preserve the count.

See `docs/STYLEE_WARDROBE_GRID_SPEC.md` for composition, responsive, and
acceptance rules.

Run `npm run wardrobe-density:check` after any wardrobe card, grid, header,
search, choice-chip, or Tab Bar change. Use the account-independent visual
preview documented in `docs/STYLEE_DESIGN_SYSTEM_V3_8_MIGRATION.md` for manual
multi-size review.
