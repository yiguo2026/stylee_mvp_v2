<callout icon="star" bgc="4">  
**评测定位：** 用一批冻结的 query 让模型从 800+ 单品里搭出整套，交给大众评审判断「搭得对不对、好不好看、想不想穿」，产出 v1 baseline，并支撑后续模型 / Prompt 版本对比。  
- **最大调整 1｜先机器校验、再人评：** 品类完整、季节温度、场合、性别、指定必含单品、单品是否真实存在于池中——这些能自动判的先过一道 pass/fail，人只评「已通过约束」的搭配的主观质量。  
- **最大调整 2｜个性化不进大众评审：** 大众看一套图判断不了「够不够懂我」。个性化只用「同 query 不同画像」的 A/B 小样本，交给熟悉用户的评审，不摊进大众总分。  
- **最大调整 3｜评审必须看图、维度砍到 3+1：** 评审物料是单品抠图拼成的整套 look，不是文字清单；大众只打「场景契合 / 好看协调 / 我愿意这么穿」三项，加一个总体满意度。  
</callout>

## 这次要测什么，边界在哪

一句话：验证「给一句需求，模型能不能从衣橱（这次用 800+ 单品池模拟）里挑出一整套既合理又好看的搭配」。

「搭配能力」要拆成三件事，别压进一个分里：

- **选品合不合理**：挑出的每件单独看，符不符合场景、季节、性别；
- **组合搭不搭**：几件拼在一起，色彩、风格、廓形、层次是否协调——这才是搭配能力的核心，也是最容易被单品质量掩盖的地方；
- **场景适配**：整套配不配得上 query 说的场合、天气、风格。

Non-goal：不评抠图质量与商品好坏；不评线上点击 / 转化（离线阶段拿不到）；不在这一版做大规模个性化评估，只做小样本 A/B 探针。

## 对原 5 维评分的复盘

原文档的 5 维（意图匹配 30% / 审美质感 25% / 个性化深度 20% / 实穿性 15% / 创意惊喜 10%）作为「模型诊断维度」站得住，但直接搬给大众打分有两个硬伤：一是**有的维度大众在只看一套搭配时根本判断不了**，二是**权重是拍的、缺乏依据**。逐条处理如下。

## 指标口径与版本对比

- **North-star：** 总体满意度均值 +「愿意穿」占比（≥4 分算愿意）。
- **诊断：** 三个子维度均值与分布、吐槽标签频次。
- **合规率：** Layer 0 通过率——模型约束是否真生效看这个，不看大众分。
- **权重别拍脑袋：** 不预设子维度权重，先按总体满意度排名；需要合成分时，用子维度回归总体满意度学经验权重，比 30/25/20/15/10 更有依据。
- **版本对比用 pairwise：** 比 v1、v2 时，同一 query 两版并排让评审二选一，比各打绝对分更灵敏、更省样本，直接回答「新版是不是更好」。

## 评审执行：怎么保证分数可信

大众打分最大的风险是噪声，几条纪律必须有：

- 每套搭配 ≥3 人交叉评，报告评审间一致性；
- 盲评，界面不露模型 / 版本 / 任何倾向；
- 随机出题顺序，避免疲劳偏差；
- 插入 gold 锚点（明显好、明显坏的样例）和 attention check，筛掉乱打的评审；
- 开评前给 5 个校准样例统一尺度。

## 题库与覆盖（制题）

冻结一套 golden query set（建议约 50 条，跨版本复用），balanced 覆盖以下维度的组合：

- **场景**：通勤 / 面试 / 约会 / 旅行 / 运动 / 居家 / 婚礼宾客 等；
- **风格**：法式 / 通勤 / 甜酷 / 极简 / 复古 / 运动休闲 等；
- **色系**：中性色 / 明亮撞色 / 同色系 / 莫兰迪 等；
- **季节温差**：春夏秋冬 + 极端温度（零下需外套、盛夏需透气）；
- **query 类型**：场景直给、风格直给、单品驱动（「用这条牛仔搭」）、模糊情绪、带天气约束、指定必含单品。

再补两类专项题：边界题（冲突需求 / 极端温度）测约束鲁棒性；双画像题（同 query 不同用户画像）测个性化。已有的 `queries.json` / `queries_matrix.md` 作为起点，按新框架调整补齐。
